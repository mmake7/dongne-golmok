# 🗺️ 동네골목 — ROADMAP

> v1 (파일럿) → v1.5 (구체화) → v2 (실제 검증) → v3 (확장·수익화)

이 문서는 동네골목이 시간 축에서 어떻게 진화하는지 정리한다. 각 단계는 **"끝났을 때 어떤 상태가 되어야 하는가"**로 정의.

- 1:1 시연 시 "와" 반응 70% 이상

### v1 기능 범위

- ✅ 회원가입·로그인 (Auth) — 주민 계정만. 가게 가입은 X (목업).
- ✅ 동네 인증 — 염창동 고정 (파일럿)
- ✅ 가게 목록 (정착형/이동형 토글)
- ✅ 가게 상세 페이지
- ✅ 오늘의 동네 한 줄 환영 (AI)
- ✅ 컨시어지 검색 (자연어 → 한 줄 답변)
- ❌ 가게 등록 폼 (1~2개만 데모용 라이브)
- ❌ 채팅·결제·매너온도·푸시·진짜 GPS

### v1 기술 스택 (잠정)

> DEV.md에서 dev-kickstart 에이전트로 본격 결정 예정.

- Frontend: React 18 (CDN) + Tailwind (CDN) + Babel standalone — 단일 `index.html`
- Backend: Vercel Serverless Functions (`api/*.js`)
- DB: Supabase PostgreSQL
- 이미지: ImageKit
- AI: Claude API (Sonnet 4.7)
- 함수 추정: 5개 (auth · feed · search · ai · mock-admin)

### v1 일정

> 형의 시간 자원에 따라 유동적. 마감 압박 없음.

- **Phase 1** — Week 6 Day 후반 ~ Week 7: 기획 문서·목업 데이터 완성 (현재)
- **Phase 2** — Week 7 ~ Week 8: 사이트 구현 (UI 프로토타입 → 백엔드 연결)
- **Phase 3** — Week 8: 컨시어지 프롬프트 튜닝 + 시연 시나리오 검수
- **Phase 4** — Week 8 말: Vercel 배포 + 첫 시연 가능 상태

> Quest #5 마감과 분리. 1등 양보 가능. 중요한 건 동네골목 자체.

## v2 — 실제 동네 검증 (3~6개월 후)

> "데모를 진짜로 만든다."

### 끝났을 때의 상태

- 염창동에서 **실제 가게 5~10곳** 등록·운영
- 실제 주민 50명 이상 가입
- 한 달간 컨시어지 질문 200건 이상 처리
- 단골 등록 기능 동작

### 핵심 미션

#### 1. 실제 가게 모집

- 형이 직접 한 곳씩 방문 (염창동이라 가능)
- 가게 사장님 셀프 가입 폼 또는 형의 대리 등록
- 처음에는 형의 단골 가게 활용 (떡집·정육점 등)
- **법적 준비**: 가게 정보 게시 동의서

#### 2. 단골 등록 기능

- 주민이 좋아하는 가게를 "단골 등록"
- 그 가게의 입고/위치 알림을 우선적으로
- v1의 "오늘의 동네 한 줄"이 단골 가게 정보 위주로 진화

#### 3. 컨시어지 정확도 향상

- 실제 사용 로그 기반 프롬프트 개선
- 응답 부정확 패턴 식별 + 수정
- 페르소나 톤 검증 (실제 동네 주민이 친근하게 느끼는가)

#### 4. 데이터 정확도

- 실제 영업시간 / 휴무일 / 위치 검증
- 이동형 가게의 정기 일정 데이터 확인
- 주민이 "오늘 와있어요" 같은 알려주기 기능 (커뮤니티 기여)

### v2 운영 모드

> v2는 **반운영(half-running)** 상태. 진짜 운영을 시작하지만 부담 없이 형 혼자 가능한 규모.

- 주 1회 가게 사장님 1~2곳 새로 추가
- 컨시어지 질문 모니터링 (주 30분)
- 부정확 응답 → 데이터 보강 (주 1시간)
- 주민 피드백 채널 (간단한 의견 폼)

## v3 — 광고/PR 모델 + 외연 확장 (1년 후)

> "수익 모델 도입 + 자치구 단위로."

### 끝났을 때의 상태

- 가게 50곳 이상, 주민 500명 이상
- 광고/PR 매출 발생 (월 OOO원 단위로 시작)
- 강서구 전 동(가양·염창·등촌·가양 1·2·3) 확장
- 누리인포스 JV의 자체 IP로 정식 편입

### 핵심 미션

#### 1. 광고/PR 모델 도입

- 가게 유료 PR (월 1~3만원, "오늘의 추천" 노출 우대)
- 단, **광고가 컨시어지의 진정성을 해치지 않게** 설계 필수
- 광고 가게 vs 일반 가게 표시 명확히

#### 2. 강서구 전 동 확장

- 가양·염창·등촌 + 가양 1·2·3동 (총 6개 동)
- 동 간 인접 정보 공유 (이동형 트럭은 여러 동 순회)
- 사이트 메인에 동 선택 기능

#### 3. 누리인포스 JV 자체 IP 편입

- 형 51% / 누리인포스 49% 출자 구조에 맞춰 IP 귀속
- 형이 대표이사로 운영
- 누리인포스 기술 인력 활용 (외주 부담 절감)

#### 4. 지자체 협력 검토

- 강서구청 소상공인 지원과 미팅
- 동네골목이 강서구 소상공인 디지털화 사업 일환으로 편입 가능성
- 공공 예산 + 민간 운영의 하이브리드 모델

## Long-term Vision (3년 후)

> "서울 25개 자치구의 동마다 동네골목."

### 시나리오

- 서울 25개 자치구 → 200~300개 행정동
- 각 동마다 50~100개 가게 등록
- 자치구 단위 운영 파트너 모집 (각 동을 잘 아는 동네 운영자)
- 누리인포스 JV가 본사 역할, 동별 운영자가 가맹점 형태

### 사회적 가치

- **숨어있는 동네 경제의 가시화** — 공식 통계에 안 잡히는 비공식 상권을 데이터화
- **단골 관계의 회복** — 큰 마트·온라인이 아닌 동네 가게로 발길
- **소상공인 디지털 격차 해소** — 인스타·블로그 못 하는 사장님도 사용 가능

### 비즈니스 모델 (성숙기)

- 광고/PR — 가게 유료 PR (메인)
- 지자체 협력 사업 — 공공 예산 (보조)
- 데이터 라이선싱 — 동네 비공식 상권 데이터를 연구·정책에 제공
- 프랜차이즈 — 동별 운영자에게 기술·브랜드 라이선스

## Risk & Mitigation

> 각 단계의 리스크와 대응.

### v1 리스크

| 리스크 | 대응 |

## Decision Points (의사결정 분기점)

> 각 단계 끝에서 형이 결정해야 할 큰 질문들.

### v1 → v1.5 진입 시

- 데모 반응 만족? (10명 중 7명 이상 "와")
  - YES → v1.5 진입
  - NO → v1 보강 (컨시어지 톤·데이터·디자인)

### v1.5 → v2 진입 시

- 첫 협력 의사 표명 받음?
  - YES → v2 진입 (실제 모집)
  - NO → v1.5에서 추가 정교화 (특히 AUDIENCES.md)

### v2 → v3 진입 시

- 가게 30곳 / 주민 200명 이상?
- 사용자 만족도 검증됨?
- 형의 시간 자원으로 유료 모델 운영 가능?
  - 모두 YES → v3 진입
  - 하나라도 NO → v2 연장

## Project Identity Reaffirmed

> 형이 며칠 뒤에 봐도 잊지 말 것.

이 프로젝트는:
- 학습용 quest가 **아님** (그건 6주차에서 분리됨)
- 1등 마감 위한 게 **아님**
- 형의 진짜 사이드 프로젝트, 진짜 만들 것
- 투자자/협력자에게 보여줄 파일럿
- 누리인포스 JV의 첫 자체 IP 가능성
- 형이 대표이사로 운영할 비즈니스의 시작

> "수능시험도 아니고 결국 내 발전을 위한 거"

이 한 줄을 기억하고 천천히 가자.
