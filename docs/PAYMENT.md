# 💳 동네골목 — PAYMENT

> 선결제로 골목 상권의 카드 결제 통증을 푼다.

이 문서는 동네골목이 **결제(선결제)**를 어떻게 다루는지 정리한다. 결제는 v1에서는 메타데이터 표시만, v2부터 TossPayments 통합 + 정산 시스템으로 들어가는 핵심 기능이다.

---

## 왜 결제인가 — 골목 상권의 진짜 통증

골목 상권의 작은 가게들은 카드 결제 인프라가 부족하다. 4가지 패턴:

### 1. 트럭·노점 — 카드 단말기 부재. 현금만.

화요 순대차·목요 양말차·주말 과일트럭. 단말기를 들고 다닐 수 없거나 비용 문제로 도입 못 함. 카드만 들고 온 손님은 헛걸음.

### 2. 1인 메이커·공방 — 단말기 비용·부가세 부담으로 회피.

도자·캔들·비누·한지 같은 1인 작가들. 가맹·단말기 월 비용 + 부가세 부담이 그들의 마진에 비해 큼. "현금이나 계좌이체로요" 가 일반.

### 3. 재래시장 가게 — 단말기 있어도 "카드 안 받습니다" 관행.

생선·반건조·닭·채소 가게. 단말기는 있어도 카드 결제는 부가세 처리·매출 노출 부담으로 거부. 손님이 "카드 돼요?" 하면 "현금이 나아요" 답함.

### 4. 시즌·이동형 — 상시 운영 X 라 단말기 필요성 낮음.

호떡차 (겨울만), 붕어빵 (11월~3월), 홍게 노점 (시즌). 단말기 가맹 비용 대비 영업 일수가 짧아 도입 안 함.

---

## 동네골목이 푸는 방식

```
사용자  →  앱에서 미리 결제  →  가게에서 결제 화면 보여줌  →  물건만 받음
                  ↓
        동네골목이 결제 보관
                  ↓
    주 1회 또는 월 1회 정산  →  가게로 송금
```

**핵심**: 가게는 카드 단말기가 없어도 카드·간편결제 손님을 받는다. 사용자는 카드만 들고 가도 산다.

---

## 결제 모델 — v1·v1.5·v2 단계별 도입

### 모델 A. 단순 선결제 (v2 도입 1순위)

- 사용자: 메뉴 보고 결제 → 결제 완료 화면
- 가게: 화면 확인 → 물건 줌
- 정산: 주 1회 또는 월 1회 동네골목 → 가게 정산
- **적합**: 떡집·반찬가게·정육점·1인 메이커

### 모델 B. 예약 + 선결제 (v2 도입 1순위, 이동형 강력)

- 사용자: 시간 지정 + 결제 (예: "내일 오후 6시 한과 한 봉지")
- 가게: 예약 시간에 맞춰 준비
- **적합**: 이동형 트럭·시즌 노점·베이커리·한과집

### 모델 C. 충전식 단골 결제 (v3 도입 검토)

- 단골 가게에 미리 충전 → 갈 때마다 차감
- v3 영역. v1·v2에선 안 함.

## 단계별 도입 계획

### v1 파일럿 (Week 7~8)

- TossPayments 통합 X
- 가게 데이터에 `payment_options` 필드 추가
  - `card` / `cash` / `transfer` / `prepay` 4가지 중 다중 선택
- 가게 카드(목록)에 작은 배지 (💳 / 💵 / 🏦 / 🎫) 표시
- 가게 상세 페이지에 안내문:
  > "이 가게는 선결제 가능 — v2부터 실제 결제 도입 예정"
- 데모 임팩트: 투자자가 "어 카드 안 받는 가게도 결제 가능하구나" 한눈에 인식

### v1.5 (Week 8~12)

- 결제 UI 디자인 정교화 (따뜻한 흙 톤 안에 자연스럽게)
- TossPayments 가맹 절차 검토
- 정산 주기·세금 처리 정책 수립
- 가게 사장님 사업자 등록 정보 수집 폼 디자인

### v2 (3~6개월)

- TossPayments 실제 통합 (테스트 → 운영 키 전환)
- **모델 A 우선 도입** (단순 선결제)
- 정산 시스템 구축 (주 1회 또는 월 1회)
- 환불·취소·분쟁 처리 정책
- **모델 B (예약 선결제)** 는 모델 A 안정화 후 추가

### v3 (1년 후)

- **모델 C (충전식 단골)** 검토
- 광고/PR 모델과 결합 (예: "이 가게 선결제 5천원 이상 시 5% 적립")

---

## 수수료 정책

- **v1·v2**: 동네골목 수수료 0%. 가게가 받는 금액 = 사용자가 결제한 금액.
- **v3**: 광고/PR 모델로 수익. 결제 수수료는 검토 영역(아직 미정).

이유: 동네골목의 1순위 미션은 **"동네 가게가 살아남게"** 함이다. 수수료는 가게의 마진을 깎아 미션과 충돌한다.

---

## 법적 검토 항목 (v2 진입 전 필수)

- 전자상거래법 준수 (선결제 매개자 의무)
- 가게 사업자 등록 정보 수집 동의서
- 환불 규정 (사용자 vs 가게 vs 동네골목 책임 범위)
- 부가세 처리 (동네골목이 매개자라면 가게 부가세 처리 부담은 가게)
- 개인정보 처리 (결제 내역 보관 기간)
- 분쟁 처리 절차 (사용자가 "안 받았다"고 주장 시)

---

## TossPayments 통합 노트 (v2)

- 테스트 환경에서 모델 A부터 검증 (테스트 키 확보 완료)
- 정산은 동네골목이 주체 (가게 → 동네골목 → 정기 정산)
- 가게별 정산 계좌 등록 필요
- 결제 위젯은 TossPayments 표준 사용 (직접 구현 X)

---

## Anti-Scope (결제 도입에서 안 할 것)

- 즉시 정산 (주 1회 / 월 1회만)
- 다양한 PG (TossPayments만)
- 외화 결제 (KRW만)
- 가상자산 결제 (X)
- 분할 결제 / 카드 할부 (v2 안정화 후 검토)
