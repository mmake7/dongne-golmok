# 💡 동네골목 — CONCEPT

> 동네 친구에게 묻는 것처럼.

이 문서는 동네골목의 **본질이 무엇인가**를 정리한다. MISSION.md가 "왜·무엇·누구"라면, 이 문서는 **"느낌이 어떤가"**를 다룬다.

---

## One-Liner

**숨어있는 우리동네가게를 알고, 내 상황을 듣고, 답을 찾아주는 동네 친구.**

이 한 줄에 동네골목의 모든 것이 들어있다:
- "숨어있는 우리동네가게" → 대상 (공식 상권 바깥 모든 소규모 주체)
- "알고" → 가게 데이터 보유
- "내 상황을 듣고" → 자연어 입력
- "답을 찾아주는" → AI 컨시어지
- "동네 친구" → 톤 / 페르소나

---

## Core Concept — 동네 친구

동네골목의 핵심 비유는 **"동네 사정에 밝은 친구"**다.

### 비교: 일반 검색 vs 동네 친구

| | 일반 검색 (네이버·카카오) | 동네 친구 (동네골목) |
|---|---|---|
| 입력 | 키워드 | 자연어 ("밤 11시 순대 먹고 싶어") |
| 데이터 | 공식 등록 가게 위주 | 숨어있는 우리동네가게 포함 |
| 응답 | 리스트 + 지도 | 한 줄 답변 + 맥락 |
| 톤 | 정보 제공 | 친근한 추천 |
| 시간 인식 | 영업시간만 | "밤 11시", "주말", "지금" 모두 인식 |
| 관계 | 1회성 | 단골 발견 |

### 페르소나 — 동네 친구의 톤

동네골목 AI는 다음과 같이 말한다:

✅ **이렇게 말한다**:
- "오늘 OO떡집에 새 가래떡 나왔대요. 6시 전에 가시면 따끈할 거예요."
- "지금 11시면 순대차는 끝났을 거예요. 대신 강서로 분식집이 12시까지 해요."
- "주말이라 양말차는 토요일 저녁에 와요. 미리 가시면 사이즈 다양하대요."

❌ **이렇게 말하지 않는다**:
- "검색 결과 3건이 발견되었습니다."
- "조건에 부합하는 매장은 다음과 같습니다."
- "현재 위치 기반으로 추천드립니다."

**핵심 톤**: 친근함. 실제 동네 친구가 카톡으로 알려주는 정도의 가벼움.

> 파일럿 단계에서는 **단일 페르소나** (동네 친구 한 명). v2 이후 5주차 듀오 캐릭터 패턴(카페지기·달지기) 차용 검토.

## Differentiation — 다섯 가지 결정적 차이

### 1. 당근마켓과의 차이 (출발점이 같지만 방향이 다름)

| | 당근마켓 | 동네골목 |
|---|---|---|
| 주인공 | 안 쓰는 물건을 가진 주민 | 숨어있는 우리동네가게 사장님 |
| 거래 | 앱에서 약속 → 직거래 | 그냥 가게 가서 사면 끝 |
| 핵심 정보 | 팔 물건의 상태·가격 | 오늘/지금 — 입고·위치·시간 |
| 관계의 모양 | 1회성 거래 | 동네 단골 — 지속되는 관계 |
| AI 사용 | 추천 (행동 기반) | 컨시어지 (자연어 대화) |

**차용한 것**: 동네 인증 패턴, 등록·목록·상태값 UX.
**비튼 것**: 사용자 주체, 거래 모양, 관계 깊이, AI 활용 방식.

### 2. 네이버 지도/카카오맵과의 차이

지도는 **공식 등록된 가게**를 보여준다. 동네골목은 **공식 등록되지 않은 가게**를 본다. 트럭·노점·1인 메이커가 핵심.

### 3. 인스타그램·블로그와의 차이

인스타·블로그는 **가게가 직접 콘텐츠를 만들어야** 한다. 동네 사장님 대다수가 이걸 못 한다. 동네골목은 **한 줄 등록만으로 충분**하게 설계된다.

### 4. 일반 AI 챗봇 (ChatGPT, 클로드)과의 차이

일반 AI는 **인터넷 일반 지식**을 가진다. 동네골목 AI는 **염창동 50개 가게의 오늘 정보**만 안다. 좁고 깊다.

### 5. 동네 단톡방·맘카페와의 차이

단톡방은 **사람의 기억과 부지런함**에 의존한다. 정보 누적·검색이 안 된다. 동네골목은 **AI가 정리·검색**해준다. 단톡방의 정보 가치를 구조화한다.

## Visual / Tone Concept

### 사이트 디자인 — 따뜻한 흙·크라프트 톤

> PPT는 5주차 PRIME 흑백 미니멀 톤 유지 (일관성).
> 사이트는 **따뜻한 흙·크라프트 톤** (동네 골목의 정서).

**컬러 팔레트** (잠정):
- 메인: 크라프트 베이지 (#E8DFD3) 또는 따뜻한 옐로우 (#F5E6C8)
- 텍스트: 짙은 갈색 (#3E2A1F)
- 강조: 단풍 오렌지 (#D87844) 또는 짙은 적갈색 (#A0413A)
- 보조: 모스 그린 (#7A8B5C) — 이동형 가게 표시

**폰트** (잠정):
- 헤더: 노토 세리프 KR (정성스러운 손글씨 느낌)
- 본문: Pretendard (가독성)
- 강조 한 줄: 손글씨 폰트 (예: 카페24 빛나는별)

**비주얼 모티프**:
- 골목길 일러스트 또는 손그림 동네 지도
- 가게마다 손그림 아이콘 (떡집·트럭 등)
- 종이 질감 / 크라프트지 배경

### Anti-Visual — 이렇게는 안 한다

❌ 차가운 IT 톤 (네이비·검정·산세리프만)
❌ 당근마켓의 주황 + 파스텔 톤 (이미 점유된 영역)
❌ 인스타그램풍 글래스모피즘
❌ 챗GPT풍 단순한 챗봇 UI
❌ 매끈한 플랫 디자인

## Interaction Concept — 두 가지 진입로

사용자가 동네골목에 들어오는 길은 두 가지.

### 진입로 A — 둘러보기 (수동적)

```
앱 진입
  ↓
[오늘의 동네 한 줄]
"오늘 염창동에는 한과집 새 가래떡, 화요일이라 순대차도 와있어요."
  ↓
[가게 목록]
정착형 / 이동형 토글, 카테고리 필터
  ↓
가게 상세
```

**누가 쓰는가**: 별 목적 없이 "오늘 동네에 뭐 있나" 보는 사람.

### 진입로 B — 묻기 (능동적)

```
앱 진입
  ↓
[검색창 / 컨시어지]
"밤 11시 순대 먹고 싶어"
  ↓
[AI 한 줄 답변 + 추천 가게]
"지금 11시면 순대차는 끝났을 거예요.
 대신 강서로 분식집이 12시까지 해요."
  ↓
가게 상세
```

**누가 쓰는가**: 구체적인 욕구가 있고, 동네에 그게 있는지 모를 때.

**v1에서는 두 진입로가 하나의 화면에 공존**한다. 화면 상단 한 줄 환영 + 그 아래 검색창 + 그 아래 가게 목록.

## Differentiation Story — 한 페이지로 설명한다면

> 투자자/협력자에게 30초 안에 설명하는 시나리오.

---

지금 우리는 동네에 뭐가 있는지 모릅니다.
정육점에 갔는데 한우가 없으면 그날 저녁이 어디로 가야 할지 모릅니다.
역앞 다마코치는 오늘 와있을지, 순대차는 이번 주 화요일에 오는지,
지도에도 인스타에도 없는 가게들이 너무 많습니다.

**동네골목은 이 정보를 AI 컨시어지가 정리해줍니다.**

"밤 11시 순대 먹고 싶다" 라고 던지면,
"오늘 화요일 순대차는 9시까지였어요. 강서로 분식집이 12시까지 해요." 라고 답합니다.

큰 마트 검색이 아닌, 진짜 동네를 아는 친구에게 묻고 답을 받는 겁니다.

파일럿은 강서구 염창동.
50개 가게 목업으로 시작해, 6개월 안에 실제 가게 5~10곳 모집.

3년 후 서울 25개 자치구의 동마다 작동하는 AI 컨시어지 네트워크.
숨어있는 동네 경제를 가시화하고, 단골 관계를 회복합니다.

## Key Concepts (용어 정의)

> 이 프로젝트에서 자주 등장하는 단어의 정의.

| 용어 | 정의 |
|---|---|
| **숨어있는 우리동네가게** | 공식 상권(네이버 지도·인스타)에 안 잡히는 모든 소규모 주체. 떡집, 양장점, 1인 메이커, 트럭, 노점 모두 포함. |
| **AI 컨시어지** | 사용자의 자연어 질문을 받아 동네 데이터에서 답을 찾아 한 줄로 응답하는 AI. 동네 친구 톤. |
| **오늘의 동네 한 줄** | 앱 진입 시 오늘 등록된 우리 동네 정보를 AI가 한 줄로 묶어 환영하는 메시지. |
| **정착형** | 고정 위치에 늘 있는 가게. 떡집·세탁소·정육점 등. |
| **이동형** | 정기적/비정기적으로 위치를 바꾸는 주체. 트럭·노점·떨이차. |
| **단골** | 동네골목이 추구하는 관계의 모양. 1회성 거래가 아닌 지속되는 관계. |
| **파일럿** | v1 단계. 염창동 한정. 목업 데이터로 데모. 투자자/협력자 검증용. |

## What Could Go Wrong (예상 함정)

### 1. AI 응답이 "동네 친구"답지 않을 위험

LLM은 기본적으로 형식적인 톤을 갖는다. 프롬프트 엔지니어링으로 친근한 톤을 만들어야 함. v1에서 응답 50개 정도를 직접 검수하고 톤 가이드 정립.

### 2. 50개 목업 데이터의 "진짜성" 부족

데이터가 어색하면 AI 답변도 어색해진다. 형이 직접 염창동을 걸으며 거리·골목 이름을 확인하고, 실제 있을 법한 가게 구성으로 채워야 한다 (목업이라도 사실적).

### 3. 데모할 때 컨시어지 시나리오 외 질문 받으면 무너짐

투자자가 "그럼 기저귀 어디서 사요?" 같은 예상 외 질문 던질 수 있다. **응답 가능 범위를 시연 전에 명시**하는 것 + 그 범위 내에서는 100% 작동하는 것이 안전.

### 4. v1 디자인이 "따뜻한 흙·크라프트"를 못 살리면

차가운 IT 톤이 되면 컨셉 자체가 깨진다. 디자인 v2 (Week 7~10 v1.5 단계)에서 반드시 톤 정립 필요.

### 5. 본 프로젝트와 quest 마감의 시간 충돌

형이 "마감 잊자"고 했지만 회사일이 빡빡해지면 본 프로젝트도 흐려질 수 있다. 주 1회 짧게라도 진행 상황 점검 권장.
